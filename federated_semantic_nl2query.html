            Stage 02 / 05
            —
            Unstructured Document Intelligence Pipeline
          

          

            Unstructured PDF Parsing (PyMuPDF + OCR) → spaCy EntityRuler → Concept & Relationship YAML
          

          

            Critical underwriting risk factors reside inside engineering fire inspection reports, appraisal slips, and loss-run affidavits. We extract layout-aware text using PyMuPDF (`fitz`) + Tesseract OCR, apply spaCy (`en_core_web_trf`) paired with deterministic `EntityRuler` token patterns, and traverse dependency parse trees to extract Subject–Predicate–Object triples into an Unstructured YAML specification.
          

        

        

          
        

      


      
      

        

          

            STEP 2.1
            PyMuPDF + OCR
          

          
PDF Layout & Text Extraction

          
Extracts text blocks, bounding boxes, and scanned tables via `fitz`, `pdfplumber`, and `pytesseract`.

        


        

          

            STEP 2.2
            spaCy EntityRuler
          

          
Rule + Transformer NER

          
Matches custom token patterns (e.g. `[{'LOWER': 'sprinkler'}, {'LOWER': 'system'}]`) alongside transformer NER.

        


        

          

            STEP 2.3
            Dependency Parse
          

          
Concept & Relation Digging

          
Traverses syntactic dependency trees (`nsubj`, `ROOT`, `prep`, `pobj`) to link entities into S-P-O triples.

        


        

          

            STEP 2.4
            YAML Artifact
          

          
Unstructured Concept YAML

          
Serializes extracted concepts, attributes, confidence scores, and relationship triples for Stage 3 reconciliation.

            Stage 03 / 05
            —
            Hybrid Ontology Alignment & Adjudication
          

          

            3-Tier Reconciliation Cascade: Fuzzy (>95%) → Semantic Embeddings → LLM Adjudication
          

          

            Candidate entity and attribute pairs between the Structured YAML and Unstructured PDF YAML pass through three sequential reconciliation gates: Gate 1: Lexical Fuzzy Matching (>95% auto-merge), Gate 2: Dense Semantic Embeddings (`text-embedding-3-large` → Merge, Relate, or Reject), and Gate 3: LLM Adjudication Call for nuanced underwriting candidate pairs.

          Interview Pitch Guide • Nexus AI Showcase #1
          
How to Present This Architecture in Your Interview

        

        
      

      

        

          
1. Structured Sources & Dual-DB Ontology YAMLs (Stage 1)

          
"In commercial insurance underwriting, a single conceptual entity is often split across multiple databases. For example, CommercialProperty has catastrophe & TIV metrics in Snowflake (`DIM_PROPERTY_ASSET`) while physical building inspection columns sit in PostgreSQL (`TBL_BLDG_INSPECTION`). Our automated schema discovery pipeline extracts three clean artifacts: Structure Ontology YAML, Semantic YAML (with standard `ACORD`/`FIBO` mappings and synonyms), and Mapping YAML."

        

        

          
2. Unstructured PDF Extraction with OCR + spaCy EntityRuler (Stage 2)

          
"Next, critical underwriting hazards live in unstructured PDF inspection reports and loss-run affidavits. Rather than running slow, expensive LLM calls over thousands of pages, we extract layout blocks with PyMuPDF (`fitz`) + Tesseract OCR, apply spaCy (`en_core_web_trf`) combined with deterministic `EntityRuler` token patterns, and traverse dependency trees to build an Unstructured Concept & Relationship YAML."

        

        

          
3. 3-Tier YAML Reconciliation Cascade (Stage 3)

          
"To reconcile the Structured YAML and Unstructured YAML accurately, we pass candidate concept pairs through three sequential gates: (1) Fuzzy Matching (>95% Levenshtein/Jaro-Winkler) for instant deterministic merges, (2) Semantic Embedding Cosine Similarity (`text-embedding-3-large`) to classify pairs into Merge, Relate, or Reject, and (3) LLM Adjudication strictly for ambiguous domain pairs like matching PDF `Fire_Suppression_Grade` with Snowflake `PROTECTION_CLASS_CD`."

        

        

          
4. Neo4j Virtual Graph & Cypher-to-SQL Execution (Stages 4 & 5)

          
"The reconciled ontology populates our Neo4j Virtual Graph (VG) where every node stores its physical SQL table/column lineage, sample values, description, and synonyms. When a user asks a Natural Language question, our agent takes the Neo4j Schema + Property Graph JSON, converts NL into Cypher first, executes Cypher on Neo4j to retrieve the exact SQL join path and resolved synonyms, and synthesizes an executable SQL query that hits the SQL database with 94.8% execution accuracy."
